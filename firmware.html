How we work

Hardware and software, designed together.

When one team designs the board and writes the code, problems get solved in the right place. A timing issue might be cheaper to fix in the layout, or a missing pin might be better handled in software. We make those trade-offs as we go, instead of discovering them at integration.

Our code is version-controlled and reviewed, and the logic that can be tested on a PC is tested there as well as on the target. Bootloaders and field updates are planned in from the start, so a product in the field can be improved.

At hand-over you get the source code, build instructions and everything needed to program and test the device.

Questions

Common questions.

Which microcontrollers and FPGAs do you use?

We choose the part that suits the product: cost, power, peripherals, tools and how reliably it can be bought. We are not tied to one vendor.

Can you take over existing firmware?

Yes. We can review an existing codebase, fix problems, add features, or port it to new hardware.

Do we get the source code?

Yes. You receive the source, the build instructions and the tools needed to program and test the device.

Do you use Rust for embedded work?

Where it suits the project. Rust removes whole classes of memory bugs, but C and C++ have wider vendor support. We will recommend whichever fits your hardware and your team.
